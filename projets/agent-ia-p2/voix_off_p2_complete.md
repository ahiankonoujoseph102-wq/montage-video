A-13 [démo : zoom sur les trois corrections] Les trois corrections : au départ, les paiements Mobile Money sont vérifiés à la main, sur capture d'écran. Pas de deuxième nom de domaine pour les sites des clients. Et les prix des modèles d'IA ne sont que des estimations.

A-17 [démo : copier le compte rendu] Je copie son compte rendu en entier.

A-18 [démo : le coller chez le chef de projet] Je l'envoie à mon chef de projet, tel quel. Pas besoin d'expliquer : il comprend tout seul.

A-23 [illustration : la pull request] Une pull request, c'est simple. Claude Code travaille sur une copie de votre projet. Quand le travail est vérifié, on fusionne cette copie dans le dépôt, votre coffre-fort. Fusionner, c'est ranger le travail terminé à sa place.

A-24 [démo : GitHub] Vous pouvez fusionner vous-même sur GitHub : vous ouvrez la pull request, vous descendez en bas, vous touchez « Merge pull request », puis « Confirm merge ».

A-29 [carte] Et quand une réponse du chef de projet vous semble bizarre, ou que vous ne la comprenez pas, discutez avec lui. Posez vos questions. Et si vous restez bloqué, je suis là : vous avez un formateur qui a déjà fait plusieurs projets.

## VIDÉO 2B — Le moteur et le cerveau de votre agent

B-01 [titre] Partie 2B : le moteur et le cerveau de votre agent.

B-02 [démo : le chef annonce l'étape 2] L'étape 1 est validée. Le chef de projet m'explique ce qui change à l'étape 2 : l'agent va commencer à travailler pour de vrai.

B-03 [démo : zoom sur les deux comptes] Pour cela, il me demande deux comptes. Anthropic, le cerveau de l'agent : c'est payant à l'utilisation. Et E2B, les ordinateurs virtuels de l'agent : il y a un crédit gratuit au départ. Et c'est moi qui placerai les clés dans les réglages.

B-04 [démo : mon message sur Gemini] Je ne suis pas d'accord sur un point. Anthropic coûte cher. Alors je lui écris : et si j'utilisais Gemini comme cerveau de l'agent, puisqu'il a une offre gratuite ?

B-05 [carte] Vous voyez : c'est vous le patron. Quand une proposition ne vous convient pas, dites-le et discutez avec votre chef de projet.

B-06 [démo : sa réponse] Il me répond : c'est une bonne idée pour la phase de construction, mais il y a deux limites à connaître.

B-07 [démo : zoom sur la première limite] Première limite : le moteur prévu au départ, le Claude Agent SDK, ne marche qu'avec Claude. Pour utiliser Gemini, il faut changer de moteur.

B-08 [démo : zoom sur la deuxième limite] Deuxième limite : avec de vrais clients, l'offre gratuite de Gemini ne suffira pas.

B-09 [démo : je ne comprends pas] Je n'ai pas bien compris sa recommandation. Alors je lui demande de me l'expliquer plus simplement. N'ayez jamais honte de demander.

B-10 [illustration : la voiture et le carburant] Il m'explique. Un agent de programmation a deux parties. Le moteur, c'est le programme qui fait agir l'agent : lire, écrire, travailler sur les fichiers. Le cerveau, c'est le modèle d'IA qui le fait réfléchir.

B-11 [illustration : la voiture] Le moteur prévu au départ n'acceptait qu'un seul cerveau, Claude, qui est payant. C'est comme une voiture qui ne roule qu'avec une seule marque de carburant, la plus chère.

B-12 [illustration : la voiture qui accepte plusieurs carburants] Sa recommandation : changer de moteur, et prendre un moteur multi-modèle. C'est une voiture qui accepte plusieurs carburants. On peut changer de carburant à tout moment, sans reconstruire la voiture.

B-13 [démo : zoom sur la recommandation] Concrètement : pendant la construction, on branche Gemini, gratuit. Au lancement, avec de vrais clients, on choisira le cerveau qui donne la meilleure qualité.

B-14 [démo : je valide] C'est clair. Je valide. Il me donne le prompt, je le copie, et je l'envoie à Claude Code.

B-15 [démo : Claude Code fait des recherches] Claude Code commence par faire des recherches, pour trouver le meilleur moteur multi-modèle.

B-16 [démo : copier ses recherches au chef] Je copie son compte rendu et je l'envoie au chef de projet.

B-17 [démo : la réponse « OpenCode »] Le chef de projet me conseille OpenCode : un moteur vraiment multi-modèle, libre, et utilisable pour un projet commercial.

B-18 [démo : ma question] Je lui demande la différence entre OpenCode et Gemini.

B-19 [démo : sa réponse] Ce sont deux choses différentes. OpenCode, c'est le moteur : le programme qui fait agir l'agent. Gemini, c'est le cerveau qu'on branche dessus. Et plus tard, on pourra brancher un autre cerveau.

B-20 [démo : l'offre gratuite ne tiendra pas] Il me redit franchement : avec plusieurs clients, l'offre gratuite ne tiendra pas.

## VIDÉO 2C — Créer vos clés API et les ranger en sécurité

C-01 [titre] Partie 2C : créer vos clés API et les ranger en sécurité.

C-02 [rappel : la clé API] Rappelez-vous : une clé API est un code secret. Avec elle, un service sait que c'est vous, et c'est vous qui payez. Vous ne la montrez jamais à personne.

C-03 [démo : les étapes du chef] Le chef de projet me donne les étapes, une par une. Je vais les faire devant vous.

C-04 [carte] Imaginez que je ne vous aie rien montré. Que faites-vous ? Vous suivez exactement ce que dit votre chef de projet. Si vous n'y arrivez pas, faites une capture et envoyez-la-lui : il vous guidera étape par étape. Chaque projet aura ses propres étapes.

C-05 [démo AI Studio : ouvrir le site] Première clé : Gemini. Dans Google, tapez aistudio.google.com et connectez-vous avec votre compte Google.

C-06 [démo : les questions de Google] La première fois, Google pose quelques questions. Lisez, cochez, puis touchez Continuer.

C-07 [démo : Clés API] Ouvrez « Clés API ».

C-08 [démo : Créer une clé] Touchez « Créer une clé ».

C-09 [démo : nommer la clé] Donnez un nom à la clé, par exemple le nom de votre projet. C'est facultatif.

C-10 [démo : créer un projet] Choisissez « Créer un projet », puis validez.

C-11 [démo : la clé s'affiche, floutée] Votre clé s'affiche. Touchez Copier. Sur l'écran, je l'ai floutée : vous, vous ne la montrez jamais.

C-12 [démo E2B : ouvrir le site] Deuxième clé : E2B. C'est ma première fois sur ce site : je découvre avec vous. Ouvrez e2b.dev et touchez « Commencer à construire ».

C-13 [démo : s'inscrire avec GitHub] Inscrivez-vous avec votre compte GitHub, puis autorisez l'accès.

C-14 [démo : code reçu par e-mail, flouté] E2B vous envoie un code de vérification par e-mail. Ouvrez votre messagerie, copiez le code, puis collez-le. Ce code aussi est secret.

C-15 [démo : le tableau de bord] Vous êtes dans le tableau de bord. Ouvrez « API Keys ».

C-16 [démo : créer la clé] Touchez « Créer une clé », donnez-lui un nom, puis validez.

C-17 [démo : copier la clé, floutée] Copiez la clé. Là encore, je l'ai floutée.

C-18 [carte « Où ne pas ranger vos clés »] Dans la vidéo, j'ai collé mes clés dans mon bloc-notes, pour ne pas les oublier. Ne faites pas comme moi : un bloc-notes n'est pas un coffre-fort. Collez vos clés directement dans Claude Code, ou gardez-les dans un gestionnaire de mots de passe. Jamais dans WhatsApp, jamais sur une capture d'écran.

C-19 [démo : le chef explique où placer les clés] Le chef de projet m'explique où placer les deux clés : dans l'environnement de Claude Code.

C-20 [démo R1 : menu des environnements] Ouvrez Claude Code. Touchez le menu des environnements, choisissez l'environnement de votre projet, puis touchez Modifier.

C-21 [démo R1 : variables d'environnement] Descendez jusqu'à « Variables d'environnement ».

C-22 [démo R1 : taper les deux lignes] Écrivez une ligne par clé : le nom de la clé, le signe égal, puis la clé, sans espace. Le chef de projet vous donne les noms exacts. Pour moi : GEMINI_API_KEY et E2B_API_KEY.

C-23 [démo R1 : Enregistrer] Touchez « Enregistrer les modifications ».

C-24 [démo : Claude Code ne voit pas les clés] Je demande à Claude Code de vérifier. Il me répond : je ne vois pas les clés. Pourquoi ?

C-25 [illustration : la maison et la pièce] Le chef de projet m'explique. L'environnement, c'est comme une maison : on y range les clés. La session, c'est une pièce de la maison. Une session ouverte avant d'avoir rangé les clés ne les verra jamais.

C-26 [démo : l'erreur de l'environnement] Et j'avais une deuxième erreur : j'avais mis les clés dans l'environnement « Default », pas dans celui de mon projet. Ce n'est pas grave : avec des captures, le chef de projet m'a guidé pas à pas.

C-27 [démo R1 : nouvelle session] La solution : touchez « Nouvelle session ».

C-28 [démo R1 : choisir le dépôt et l'environnement] Choisissez votre dépôt et l'environnement où vous avez rangé les clés.

C-29 [démo R1 : demander la vérification] Demandez à Claude Code de vérifier qu'il voit les clés, sans jamais les afficher.

C-30 [démo : « les deux clés sont présentes »] Claude Code répond : les deux clés obligatoires sont présentes. Il fait un petit essai avec Gemini et E2B : les deux services répondent. Il lance l'étape 2.

C-31 [carte « Si Claude Code ne voit pas vos clés »] Si Claude Code ne voit pas vos clés, vérifiez trois choses : vous avez touché Enregistrer ; vous avez ouvert une nouvelle session ; et vous avez choisi le bon environnement. Si vous êtes bloqué, envoyez une capture à votre chef de projet, sans clé visible.

C-32 [fin] Dans la prochaine vidéo, on suit la construction jusqu'au bout.
